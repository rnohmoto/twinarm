0. 全体像（何が何に繋がるか）

Magician 本体にカメラ端子はありません。カメラは PC に USB で繋ぎ、PC が画像から座標を作り、PC が Magician に USB シリアルで動作を指示します。純正のビジョンキットも同じ形です。

2. Magician の初期設定

2.1 機種を見分ける（最初の 1 分）

見た目機種このマニュアルでの扱い
4 軸・制御器が本体に内蔵・USB 端子が本体にあるMagician（初代）そのまま進める（pydobot）
白基調・別筐体の「Magic Box」が付くMagician Liteおおむね同じ手順で動く報告あり。動かなければ robotics 91_ §1.3 へ
6 軸・ベースにリング状の表示灯・Ethernet 端子Magician E6別の通信方式（TCP/IP）。このコードでは動かない → 先に連絡

2.2 電源とホーミング（電源を入れるたびに必要）

  1. 吸盤キット（エアポンプ）を本体に取り付け、ポンプの配線を本体の端子に繋ぐ（付属の説明書の図どおり）。
  2. AC アダプタ（12V）を本体に繋ぎ、USB ケーブルで PC と繋ぐ。
  3. 電源スイッチを入れる。腕に触れずに待つ。
  4. 本体のキーを 2 秒長押し → ホーミング（腕が原点を探して動く。LED が青点滅 → 緑になれば完了）。初代 Magician は電源を入れるたびにこの操作が必要（位置の記憶が電源で消えるため）。
  5. ホーミングが終わるまで作業域に手を入れない。
安全: 初代 Magician には衝突検知がありません（脱調検知のみ）。動作中は手を入れない。止めるときは本体の電源スイッチ。来場者は仕切りの外。

2.3 ドライバと USB シリアルの確認

Mac: ターミナルで ls /dev/tty.*。/dev/tty.usbserial-XXXX か /dev/tty.SLAB_USBtoUART が増えていれば認識済み。出ないときは Silicon Labs の CP210x VCP ドライバ（macOS 用）を入れて再接続。

Windows: デバイスマネージャーの「ポート (COM と LPT)」に「Silicon Labs CP210x USB to UART Bridge (COMn)」。出ないときは CP210x ドライバを入れる。

Linux: カーネル標準（/dev/ttyUSB0）。

関門 2: ホーミングが終わり LED が緑、PC にシリアルポートが見えている。ポート名をメモ（§4 で使う）。

3. カメラの設置と「勝手に変わらない」設定

3.1 なぜ「固定」が要るか

このシステムは色（HSV）で物を見つけ、画像の位置を mm に変換します。カメラが露出・ホワイトバランス・フォーカスを自動で変えると、色のしきい値が外れたり像の倍率が変わったりして、拾い損ねや数 mm のずれが出ます。純正ビジョンキットも固定焦点レンズを使い、国内の実務例でも「高さでピントが合わず認識率が落ちた」報告があります。対策は 2 つで、どちらも C920n で可能です。

  • AF を止める: check_camera.py が OpenCV から自動露出を切り、効いたかを読み戻して報告します。AF は CAP_PROP_AUTOFOCUS=0（Windows／Linux）。Mac は OpenCV から触れないので、Logi Tune（対応機種なら）か OS 側で固定します。
  • 固定焦点のカメラを選ぶ: Elgato Facecam MK.2（30〜120cm 固定焦点・設定を本体に保存）なら、PC を替えても同じ状態が再現します。C270n も固定焦点ですが画角 55° と狭く、合焦距離が高さに合わない例があります。

3.2 置き方

  1. スタンドをカメラが真下を向くように組み、レンズ中心を机から 45cm（C920n）に。メジャーで測る。
  2. Magician の作業域（本体の前方、半径 32cm の半円）が画面に入るように位置を決める。作業域の外側 10% は使わない。
  3. スタンドを机に固定（クランプ・テープ）。ケーブルも固定し、引っかけても動かないようにする。
  4. 照明を作業域の上に置き、影が 1 方向に長く出ないようにする（面光源かリングライト）。
関門 3: 作業域全体が写り、カメラは手で押しても動かない。

4. ソフトの準備（uv・テスト・疎通チェック）

4.1 環境を作る（初回のみ・ハード不要）

cd twinarm/dobot
uv sync                 # .venv を作る（Python 3.13・OpenCV・pydobot）
uv run pytest           # ハード無しテスト。全部 passed になること
uv run python main.py --dry-run --no-llm --text "赤いブロックを右のトレイに置いて"   # 合成画像で一巡

--dry-run は合成画像とロボットの記録だけで動くので、機材が無くても流れを確認できます。

4.2 カメラの疎通と固定の確認（カメラだけ）

uv run python check_camera.py --list        # 見えているカメラ番号
uv run python check_camera.py --index 0     # 3 秒読んで、露出/WB が効いたか・明るさが揺れないかを報告

報告の見方: 手動露出の設定値 … が効いています と 明るさは安定しています の 2 行が出れば合格。効いていません のときは Mac ならメーカーツールで固定、Windows なら --exposure -5 などを試す。スナップショットが logs/ に保存されるので、写真 05 として使えます。

4.3 Magician の疎通（読むだけ → 動かす）

uv run python check_robot.py --list                          # 候補ポートを表示（選ばない）
uv run python check_robot.py --port /dev/tty.usbserial-XXXX  # 接続して現在位置を読む（動かない）
uv run python check_robot.py --port /dev/tty.usbserial-XXXX --home        # ホーム姿勢へ動く
uv run python check_robot.py --port /dev/tty.usbserial-XXXX --round-trip  # 作業域内を 1 往復

Windows は --port COM5 のように書く。ポートは自動では選びません（間違った機器に指令を送らないため）。

設定ファイル config.json の camera.index と robot.port に、ここで分かった番号とポートを書いておくと、以後の引数が省けます。
関門 4: テスト全 passed・カメラ報告 2 行が合格・--home でホーム姿勢に動いて止まる。

5. キャリブレーション（画像 → ロボット座標）

机は 1 枚の平面なので、画像の位置とロボットの XY は 4 点の対応（ホモグラフィ）で結べます。ArUco マーカーを机の四隅に貼り、各マーカーの中心に吸盤の先端を合わせて座標を読みます。

uv run python calibrate.py --make-markers assets/markers   # 印刷用 PNG を出す → 4 枚印刷して厚紙に貼る
uv run python calibrate.py --config config.json            # カメラで 4 枚を検出 → 各マーカー中心へ吸盤先端をジョグ → space で座標を記録
  1. マーカーを四隅に貼る（図 5-1）。カメラ画面で 4 枚とも検出されることを確認。
  2. DobotStudio のジョグ、または手で腕を押して（トルクを抜いた状態）、吸盤の先端をマーカー中心に合わせ、space を押す。4 枚繰り返す。
  3. RMS が 2mm 以下なら assets/homography.json に保存される。5mm を超えるときは「机が動いた／カメラが動いた／マーカーが浮いた」を疑う。
  4. 置き場（トレイ）の中心座標も同じ要領で読み、config.json の zones に書く。
関門 5: RMS ≦ 2mm。4 隅と中央の 5 点で、画面上の物の中心に吸盤を下ろしたとき 3mm 以内に来る。

7. 初めてのピック＆プレース

uv run python main.py --tune --camera-index 0            # 検出枠を見ながら照明・HSV・面積を追い込む（q で終了・s で保存）
uv run python main.py --config config.json --robot pydobot --port /dev/tty.usbserial-XXXX --no-llm --keyboard
#   → 「赤いブロックを右のトレイに置いて」と入力（LLM 無し・ルール解析）
#   → 20 回連続で成功（吸着ミス 1 回以内）が M3 の合格

画面の操作: space 発話（キーボード入力）・h ホーム・e 非常停止・r 解除・q 終了。物理の非常停止は本体の電源スイッチ。

音声（faster-whisper）と LLM（Claude）は後から足せます: uv sync --extra voice --extra llm → ANTHROPIC_API_KEY を設定 → --no-llm --keyboard を外す。ネットが切れてもルール解析に自動で戻ります。

関門 7: 20 回連続成功。ここまで来たら robotics 側の M4（音声）・M5（LLM）・M6（連続稼働）へ。

範囲外で拒否される作業範囲ガード（AABB＋リーチ環）置き場と対象物を r=15〜30cm の帯に入れる。ガードは緩めない

9. 安全

  • 初代 Magician は衝突検知なし。動作中は作業域に手を入れない。来場者は仕切り（アクリル／ラインテープ）の外。
  • 非常停止: 画面の e、または本体の電源スイッチ。説明員が必ず 1 人、スイッチの前に立つ。
  • 電源を切るときは LED が消えるまで待ってから抜く。長時間の通電放置はしない。
  • スクリプトは「読むだけ」が既定で、動かすのは --home／--round-trip／--robot pydobot を付けたときだけ。ポートは自動で選ばない。
