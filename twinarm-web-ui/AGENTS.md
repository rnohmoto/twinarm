# AGENTS.md — twinarm-web-ui

The web teleoperation UI. Repository-wide instructions are in [`../AGENTS.md`](../AGENTS.md).

Read @README.md for the stack, the layout, and every command.

## Rules for this directory

- Run `npm` here, never at the repository root, and prefer the mise tasks over bare `npx`.
- `mise run check` leaves out the end-to-end tests. Run `mise run e2e` separately when you change
  routing, the page shell, or the mock backend.

## Feature-Sliced Design

The layer rules are in [`src/README.md`](src/README.md), and `mise run fsd` (steiger) enforces them.
Two consequences worth knowing before you place a file:

- Put new code in the lowest layer that can hold it, and create the slice's `index.ts` in the same
  commit — a slice without a public API is a lint error, not a style preference.
- Layers only import downwards. If a feature seems to need something from a page, the thing it needs
  belongs in `entities` or `shared` instead.

`steiger` is beta software. If it breaks on an upgrade rather than on real code, drop `"fsd"` from
`check`'s `depends` in `mise.toml`, note it here, and keep going — the rules stay documented in
`src/README.md` either way.

## There is no backend

`src/shared/api` holds a **provisional** contract for a backend that does not exist yet;
[README.md](README.md) describes where it came from and how it is served.

- Nothing here has ever talked to an arm, so never describe UI behaviour as evidence about hardware.
- `public/mockServiceWorker.js` is generated by `npx msw init public/`. Do not hand-edit it.
- Mocks are browser-only. Component tests inject a fake `TelemetrySource` instead — follow that
  pattern rather than reaching for MSW in Vitest.

## Scope

Teleoperation logic, a real transport, and visual design each need an explicit request.
